# 0.13.1

本版完善 Codex 插件与 companion agents 的配置归属、升级和清理行为，减少重复认证与重复环境初始化。对外 npm 包仍只有 `@zmice/zc`。

## 行为与兼容性

- 内置角色不再固定模型或推理强度，遵循宿主配置优先级。迁移只移除旧回执能够证明归属且用户未修改的默认值；保留用户自定义模型和角色注册。
- 插件、agents 和配置写入共用保护规则。遇到用户修改、归属未知或路径重定向时停止相关写入，并报告需要处理的文件；普通写入失败有回滚，卸载前检查保留角色的文件引用。
- `start`、`build`、并行调度和验证统一复用已有授权及执行环境。出现意外认证、确认或用户取消时停止相关批次，不并发登录、不循环创建新沙箱。此规范不能关闭宿主强制审批或 npm 二次验证。
- Codex 子进程具有超时、输出预算、取消和清理结果；状态区分安装配置与实际会话生效，不再用静态字段推断实际模型。
- 清理已退役的内容导入器、旧原生视觉评测路径和无生产调用的 helper。构建清除陈旧 JS，发布只使用绑定提交与源码摘要的受测 tarball。
- 修正干净 checkout 的 CLI 验证顺序，先构建内部依赖再检查类型；回滚父目录校验包含高精度创建时间，避免删除重建后的 inode 复用被误判为原目录。
- Unslop 仍通过 `start` 衔接新页面设计和已有页面重塑，沿用同一设计计划、实现和浏览器验收流程。

## 验证与限制

版本前完整门禁及实际 tarball 安装、升级、卸载验证通过。当前候选在独立 Codex app-server 中发现 72/72 技能；已核对安装内容与生成内容一致，退出清理确认，无模型调用。

新页和重塑隔离案例通过 1440px、390px 浏览器流程并检查截图，覆盖表单校验、长文本、筛选、权限、失败重试、数据保持及焦点。案例先基于旧快照生成，再按当前候选复核；这不是受控模型质量对照，也不替代真实业务或完整无障碍验收。

角色不固定模型及配置保护有安装层证据；新会话实际子模型继承尚未观察。Windows 模型评测的回环网络拒绝和异常进程树清理仍未解决，内部 A/B 执行入口保持禁用，原阻断记录保留。不得通过复制凭据、新建 home 或删除阻断标记恢复批次。

目录替换检测依赖文件系统提供的身份及创建时间精度；回滚处理普通写入失败，不承诺对抗并发恶意目录交换或进程中断。

## 升级

```sh
npm install --global @zmice/zc@0.13.1
zc platform plugin codex --upgrade --with-agents --plan --json
zc platform plugin codex --upgrade --with-agents --json
zc platform plugin codex --status --with-agents --json
```

升级前备份配置、agents 和安装回执。检查插件版本、enabled、`overallStatus=complete`、`agents.status=up-to-date`，以及 missing/drifted artifacts 为 0。存在自定义角色冲突时先保留用户文件并处理归属，不使用强制覆盖规避检查。

新会话加载更新后的角色及技能；既有会话不强制重启。安装状态通过不等于已经证明当前会话模型或权限发生变化。

## 回退

若出现加载或配置回归，安装 `@zmice/zc@0.13.0`，并使用升级前备份或对应 marketplace 提交恢复插件与受管配置。仅降级 CLI 不会降级插件。回退前保留升级后用户新增修改，不执行 npm unpublish。
