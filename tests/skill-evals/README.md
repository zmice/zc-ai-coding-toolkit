# Skill eval baseline

`fixtures.json` freezes 16 public tasks. `oracle.json` is private to the offline judge. Never pass `oracle.json`, the public expectation fields, or a judge result into the model context. `export` emits only the task input, seed, limits and fixture hash.

The review positive cases include a baseline and proposed access check with a concrete authorization bypass. Their oracle expects that finding, including path, severity and impact in the host artifact. Three adjacent negative cases prohibit review, debug or build routing only where the user explicitly requests a different task; the UI no-op case permits read-only inspection and prohibits writes.

```powershell
node scripts/skill-evals.mjs validate
node --test tests/skill-evals/runner.test.mjs
node scripts/skill-evals.mjs export review-en-explicit
node scripts/skill-evals.mjs judge path/to/host-trace.json path/to/result.json
node scripts/skill-evals.mjs summary path/to/results-array.json
```

`scripts/skill-evals.mjs` makes **no model or host calls**. It never accepts a query result from `toolkit search` or `recommend` as evidence of model selection. The separate opt-in [Codex capture adapter](../../scripts/lib/codex-eval-capture.mjs) records one actual app-server turn in a prepared disposable home/workspace. It checks effective model/effort/profile and discovery, preserves task notifications, and stops on observed time/tool/token/log limits. It does not automatically judge task correctness or translate the 16 fixtures into host executions. Do not execute fixtures in a daily workspace.

Trace JSON fields: `fixtureId`, `fixtureHash`, `sourceHash`, `contentHash` (SHA-256), `host: {surface, version}`, `model`, `effort`, `permissions`, `effectiveSkills`, `status` (`complete`, `auth-error`, `network-error`), `eventStream: "host"`, `events`, `fileDiff`, `elapsedMs`, `turns`, optional `usage`, `arm` (`baseline`, `candidate`, or `no-skill`) and `repeat` (1–3). Optional `controlledSkills` is a nonempty unique string array naming the skills disabled in the `no-skill` arm; all three arms must supply the same array when used. `sourceHash` identifies the evaluation source/seed and must stay the same across arms; each arm records its own `contentHash`. Event examples: `{ "type": "skill_loaded", "skill": "debug", "provenance": "host" }` and `{ "type": "evidence", "key": "red-reproduction", "provenance": "host" }`. `fileDiff` lists changed workspace paths and status. Capture evidence from actual tool output or inspected artifacts; model assertions alone are not host evidence. This importer checks event labels and file scope, but cannot independently authenticate a supplied trace. The result shape is in `result.schema.json`.

`validate` is the static structure layer. `judge` reports selection and behavior separately and adds a runner-side `oracleHash`. Authentication/network errors, stale fixture hashes, missing host events, or unavailable target skills yield `inconclusive`. Verified wrong routing, missing evidence, excessive duration/turns, and out-of-scope writes yield `fail`. For `no-skill`, selection means isolation. Without `controlledSkills`, the entire `effectiveSkills` catalog must be empty and no `skill_loaded` event may occur. With `controlledSkills`, those skills must be absent from the no-skill catalog and load events; background/system skills may remain. Baseline and candidate must expose every controlled skill. The same behavioral oracle still applies. This arm is valid only for fixtures with `implicit` and without `explicit` in `dimensions`; an explicit `$skill` request cannot establish skill-free behavior and is `inconclusive`.

`summary` verifies each result against the current fixture/oracle hashes and rejudges its retained host events; imported `outcome` is never authoritative. It groups each fixture/arm/configuration and requires exactly repeats 1, 2 and 3. Baseline and candidate require identical fixture, oracle, source, host, model, effort, permissions, controlled skill set and full effective skill catalog. `no-skill` is optional. When `controlledSkills` is supplied, its background catalog (effective catalog minus controlled skills) must exactly match the other arms; without it, the legacy no-skill catalog must be fully empty. The other context fields and controlled skill set must match in either mode. Each arm may have a different content hash. If supplied, no-skill also needs three runs with the same context. An incomplete, contaminated or evidence-poor no-skill arm cannot yield a passing summary. Multiple content groups or multiple skilled catalogs matching the same no-skill context are ambiguous and yield `inconclusive`. Each comparison reports behavior counts and within-arm variance for all present arms; these descriptive results do not establish statistical significance, performance improvement or ROI. Review any `regression: true` and the actual artifacts before accepting a candidate. `summary` exits 0 for pass, 1 for fail and 2 for inconclusive or malformed input. A trace with fabricated provenance can produce a false pass; event import cannot independently authenticate a supplied trace. Use a trusted host capture and review the artifacts.

In explicit `controlledSkills` mode, `no-skill` means the tested skills are unavailable; it does not mean every skill is unavailable. Background/system skills stay in `effectiveSkills` for all three arms. Do not filter them by hard-coded names. Without `controlledSkills`, the strict empty-catalog contract remains. The importer does not certify a real three-arm experiment.

`pnpm test` and `pnpm verify` run fixture validation and the runner/catalog unit tests through `scripts/run-workspace-task.mjs`. Run `pnpm test:skill-evals` for the focused runner tests, or `pnpm eval:skills validate` for static fixture validation. Real host execution remains outside default CI.

## Explicit Review content study

`review-coverage-cases.json` is a separate suite with independent private oracles. Its four cases cover a staged deletion plus same-path untracked replacement, a safe modification/rename/note, external diff, and textconv. Helpers only print markers; reading helper source is not evidence of execution. The textconv preflight verifies both converted output and the raw patch using a writable owned scratch directory. The study uses native explicit skill input to compare existing and candidate content. This is not an implicit-routing test or a no-skill experiment.

From the repository root after the workspace has been built, the Windows-only recipe is:

```powershell
pnpm eval:review <case-id> <baseline|candidate> <1|2|3> <absolute-path-to-codex.exe> --execute
```

Without `--execute` it fails before creating an experiment. The recipe currently reproduces the local Codex 0.167.0 / gpt-6-astra / high setup, requires the expected local provider configuration, and pins original body/reference hashes. `baselines/` contains frozen experimental controls, not runtime content; runtime truth remains in `packages/toolkit`. Candidate revision and content hashes must match within each comparison group. It is a bounded project study, not a portable installer or a universal evaluator. Each run creates a fresh `.cache/review-study-*` home, Git workspace and evidence directory. It verifies generated versus installed skill files, denies reads of the private suite and canonical assets, and uses no-content sandbox probes before model execution. Apps, remote plugins and discovery prefetch are disabled in the test home. Git trust is restricted to the owned fixture repository. The Windows profile uses root read access with explicit denials and a writable owned scratch directory; it is not a machine-wide confidentiality boundary.

Authentication uses a temporary copy of the existing local login. Its exact test path is deny-read probed with a non-secret placeholder before copying. The recipe deletes the copy in `finally` and compares the original login/config hashes without printing their contents. A hard process kill can bypass `finally`; after an interrupted recipe, check and remove only its owned `home/auth.json`. Keep raw events private: host notifications may include account metadata. No credentials or raw host logs belong in Git.

`frozen.json` records the fixture/oracle/content hashes and requested limits; `preflight.json` records denial checks; `evidence/capture.json`, `host-events.jsonl`, and `stderr.log` preserve actual host evidence; `receipt.json` records source/config stability. Budgets act when events arrive and may overshoot; they are not a provider billing cap. A transport `complete` means the expected turn completed, not that the behavioral oracle passed. Review actual command output, final findings and unchanged-file receipts against the private oracle. Protocol errors, mismatched turns, missing evidence, timeouts or unconfirmed cleanup stay `inconclusive`.
