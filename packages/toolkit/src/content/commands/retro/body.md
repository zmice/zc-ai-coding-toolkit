调用 sprint-retrospective 技能。回顾本轮开发，提取改进项。

1. 收集当前可访问且在范围内的数据 — Git 统计、任务完成情况、构建和 CI 指标；缺失项明确标注，不声称自动采集
2. What Went Well / What Didn't — 识别好的实践和遇到的问题
3. Spec 偏差检查 — 对比最终实现与原始 Spec，记录偏差原因
4. 流程健康度 — TDD 遵循率、验证通过率、审查覆盖率
5. 输出 Action Items — 具体改进行动 + 负责人 + 截止时间
6. 如果发现经过证据支持的可复用模式，建议进入 `/learn` 语义 workflow；是否持久化仍需单独确认能力、目标和范围

## 使用方式

在 Sprint 结束时执行 `/retro`，基于当前可访问证据引导回顾。它不是 `zc` CLI 子命令，不保证具备自动采集或持久化能力。

### 示例

```
# Sprint 结束
/retro

# 指定回顾范围
/retro 回顾过去一周的支付模块重构

# 事故后回顾
/retro 回顾昨天的线上故障处理过程
```
