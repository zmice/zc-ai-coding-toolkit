调用 `skill:frontend-ui-engineering` 构建或修改生产级用户界面。

## Routing

- 明确要求实现、修复或重构页面：进入前端实现
- 只要求审计、点评、改善建议或设计交接：先调用 `skill:ui-ux-review`，保持只读
- 需要验证真实交互、视觉、控制台或网络行为：调用 `command:qa` 或 `skill:browser-qa-testing`

## Implementation Scope

1. 读取项目设计系统、组件、数据与权限契约
2. 选择一个可独立验证的用户结果
3. 覆盖正常、加载、空、错、禁用与成功状态
4. 按 WCAG 2.2 AA 处理语义、键盘、焦点、目标尺寸和认证
5. 在代表性窄屏与宽屏执行真实验证

## Usage

在 `/ui` 后描述目标页面、用户任务和预期结果；若已有截图、设计稿或现有页面，同时提供它们。

```text
/ui 实现支持排序、筛选和分页的数据表格，并复用现有组件库
/ui 优化表单提交体验，覆盖实时验证、加载、失败恢复和成功反馈
/ui 审查现有 Dashboard 的信息层级和无障碍问题，只给证据与建议
/ui 参考指定 DESIGN.md 的信息密度与 surface hierarchy，但保留本项目 token、字体和组件 owner
```

输出必须说明范围、设计系统复用、状态与无障碍处理、实际验证及剩余风险。若使用外部视觉参考，还必须说明固定来源、迁移的抽象原则、保留的本地 owner、明确拒绝的品牌资产和对应浏览器证据。
