# 高信号测试

写或修改测试、mock、测试 helper 时读取本文件。

## 先证明测试会失败

写测试体前回答：

> 哪一个真实的错误改动会让这个测试失败？

如果答案只是“源码文字变了”“常量改了”或“mock 不存在”，改为测试依赖该决定的可观察行为。

## 独立推导期望

不要用被测函数、同一 builder 或同一算法计算 expected。优先使用手算 literal、受审 fixture 或独立 oracle。

```ts
// 低信号：两边复用同一逻辑
expect(buildQuery(input)).toBe(buildQuery(input));

// 高信号：期望独立推导
expect(buildQuery({ tag: "urgent" })).toBe('tag:"urgent"');
```

## 测行为，不测文字存在

- 脚本：运行受控输入，断言 stdout、exit code 和副作用
- 配置：加载或生成后断言消费结果
- UI：断言可访问角色、状态和交互结果
- skill / prompt：比较代理在代表性任务中的路由、动作、边界和证据
- 人类文档：没有行为契约时不为覆盖率硬写测试

## Mock 必须赚到存在价值

- 先列出真实依赖的副作用
- 只 mock 慢、外部、不可控的边界
- mock 响应保持真实结构
- 断言真实组件结果，不以“mock 被渲染/被调用”代替行为
- setup 比测试逻辑更复杂时，考虑小型 integration test

## Mutation Check

完成前在脑中或工具中尝试以下变异，确认至少一个测试会失败：

- 错误分支或错误参数
- 缺少状态变化或副作用
- 空返回或默认返回
- 零值、空值、未授权、格式错误等校验被删除
- 重试次数、顺序或边界发生 off-by-one

抓不住任何现实变异的测试，要么断言不足，要么不值得保留。
